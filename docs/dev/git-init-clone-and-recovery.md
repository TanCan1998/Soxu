# M3 显式仓库 Init、Clone 与 Worktree 损坏恢复

本次审定对应 #57，以 `origin/main` 的 `63882d1` 为基线。本文定义后续宿主本地入口的验收边界。打开普通目录、发现项目、刷新清单、守护进程启动和 Agent 接入均保持只读，任何 Git 写操作须由独立的显式请求触发。

## 1. 已核实的仓内事实

## 2. Init 与 Clone 的共同设计约束

1. 宿主只接受结构化操作和一次性授权。授权绑定请求 ID、操作、已打开的本地受控根及其目录身份、待创建的绝对目标、预期目标状态、源身份或远端策略、Git 版本及固定参数。目标位于受控根内，禁止源和目标重叠，并与其他仓库、Git 元数据及工作树池隔离。拒绝模糊路径、环境插值、路径逃逸、大小写或别名碰撞、链接、junction、reparse point 和无法核对的身份。对已存在的每段祖先使用不跟随链接的检查与目录身份比对。
2. 在受控的仓库外工作目录启动已核验 Git 二进制，用独立参数传递路径和地址。清理环境后只传所需系统变量，隔离 home、XDG、临时目录和系统/全局配置，过滤继承的 Git 配置注入、代理、SSH、终端提示、askpass 和进程跟踪配置。隔离 Git 运行时及子程序查找路径。用宿主私有空目录覆盖 `core.hooksPath`，禁止读取外部模板，拒绝用户提供的 Git 参数或 `-c` 配置。源仓库、目标或其祖先的仓库配置不能作为新请求的运行配置来源。
3. 启动前对目标做进程间独占预约，持久化预检查证据和 `Prepared`。持锁复核目录身份、目标状态和授权，在启动前持久化 `Started`。只支持能够约束外部写入或证明发布不会覆盖既有路径的平台和目录。应用锁只约束同一协调域，路径再次解析仍须防范外部进程替换。无法证明时拒绝执行。
4. 命令退出后按独立步骤重开目标，复核目标根、Git 目录布局、源和目标身份及预期配置。记录未启动、已验证、已观察部分落盘或结果未知。非零退出、超时、断电和取消均须持久记录阶段、进程树回收结果、已观察的路径/元数据/refs 以及未知项。受控运行必须有输出、时间、磁盘与进程树上限。若无法确认进程树收敛，继续保留隔离并禁用后续接入。
5. 重启或重复请求只读诊断原意图；拒绝以同一 ID 改变参数，拒绝在结果未知时重放。保留目标与外部足迹，不做自动删除、强制覆盖、移走或接入。即使 Git 自己清理了某些部分，也只记录回读证据。「未观察到残留」不足以证明从未写入。日志只保留脱敏摘要，保存与展示的边界分别受控。

## 3. 显式 Init

- **推荐首版默认目标缺失。** 在已核验、受控的父目录内为新项目预约目标，拒绝任何已有文件、目录或 Git 注册。缺失判定须区分不存在、权限错误及卷离线。打开普通目录不会触发 Init。
- **可选授权允许已验证纯空目录。** 仅在请求明确指定此模式且宿主支持目录身份约束时接纳。逐段拒绝链接和 reparse point，核对祖先无仓库覆盖，枚举包含隐藏项在内的全量目录，核对空目录自身身份和独占写入能力。持锁在启动前再核对目录身份及空目录状态。该模式允许复用用户预建目录，但多一条并发新增文件的风险。常规首版采用缺失目标，任何非空或无法验证的目录均拒绝。
- 在两种模式下拒绝已有 `.git` 目录、gitfile、损坏元数据、bare 结构、祖先仓库以及指向已登记工作树/元数据的别名。目标缺失或纯空的约束排除了接纳后代嵌套仓库。包含现有源码的普通目录迁移须单独审定。
- 固定普通非 bare 布局，使用 `git init --template= --initial-branch=main -- <目标>` 的参数语义。空模板覆盖模板选择，环境和配置仍必须隔离，禁用外部钩子。拒绝 `--separate-git-dir`、共享权限变更及继承外部模板。复核 `HEAD` 指向未出生的 `refs/heads/main`、`.git` 为受控实体目录且无外部对象依赖。失败时保留所有权和创建前状态，尤其不得删除原先由用户创建的空目录。

## 4. 显式 Clone

| 输入类别 | 首版策略 |
| --- | --- |
| 本地源 | 接受显式绝对路径，核验是宿主授权的本地普通仓库，复核源根、Git 目录及对象来源。拒绝裸路径歧义、UNC/网络挂载、链接、未知文件系统、外部 alternates 和 promisor 仓库。使用独立 `--no-local` 传输，禁用共享、硬链接优化、引用仓库和外部对象依赖。仅该模式开放 `file` 传输，由宿主从已核验路径独立构建参数。 |
| 受控 URL | 仅预置白名单的 `https://` 端点。校验规范化后的精确主机、端口及路径边界，拒绝 userinfo、查询串、片段、歧义编码和重定向。禁止一切隐式代理和凭据透传。宿主需能证明 HTTPS helper 来源、TLS 验证、连接目的地及隔离边界，无法证明时关闭此模式。首版只支持无需凭据的端点，私库授权与凭据代理另行审定。 |
| 其他 | 拒绝 `ext::`、任意 `<helper>::`、SSH/scp 风格、`git://`、HTTP、用户提供的 `file://`、URL 重写和本地/URL 混用。Git 侧同时以默认拒绝和此次操作的单协议允许列表限制传输。 |

- **目标必须缺失。** 即使 Git 支持已存在的空目录，Soxu 仍按已占用处理。保留完整请求与目的地身份，先复制仓库元数据和对象，再进行独立的受控检出。首版固定 `--no-checkout`、`--no-recurse-submodules`、`--template=`，拒绝用户注入 `--upload-pack`、`--config` 等参数。拒绝 partial/shallow clone（例如 `--filter`、`--depth`），复核无 promisor、shallow 和 alternates，随后保持禁止按需 fetch。只在进程作用域打开批准的传输协议。
- 将远端 HEAD 解析到可核对的分支与完整提交 OID，处理空远端、无效或歧义 HEAD。只有满足检出前提的仓库才可进入受控检出；空仓库可报告已克隆、无可检出提交。工作树发布前拒绝 symlink（树模式 `120000`）、gitlink（`160000`）、平台别名、目标路径逃逸以及可能启用 `clean`/`smudge`/`process` 的配置和属性来源。禁止自动执行钩子、Git LFS、外部过滤器、子模块、维护任务及项目脚本。对象成功接收不授权安装或启动任何项目能力。
- 地址、重定向和配置在写日志前脱敏。不要将原始 stderr、授权头、凭据、用户目录或任意 URL 拼入错误、命令行记录或遥测。注册项目并启用 Agent/MCP 之前，分别通过仓库复核、检出发布复核和独立宿主接入授权。失败、取消与超时的部分落盘由底层标记禁用并报告影响范围，清理只走下一节的恢复入口。

## 5. Worktree 池状态与恢复授权

诊断采集可信源仓库的清单、协调域内的意图与检出状态，再按宿主已有的路径访问权限核对卷和目录身份。快照中分别记录观察时刻、可确认事实和证据缺口。清单中的外部路径只作为值展示。禁止根据路径字符串打开任意位置或推定存在永久丢失。

| 观察 | 应补齐的只读证据 | 恢复决策 |
| --- | --- | --- |
| `locked`，有效保护锁 | 记录锁理由、活跃租约/任务和保留登记，确认卷及同一工作树身份。 | 保留锁，等持有人结束或同意撤销。无任务进程本身不能排除离线卷的保护需求。 |
| `locked`，疑似孤立锁 | 确认锁的目标仍是同一注册，协调域无活动写入，有所有者裁决及锁失效证据。 | 只在明确请求解锁后进入单注册 `unlock` 预览。未知所有者、卷离线或记录不一致时保留锁。 |
| `prunable` 或路径不可达 | 逐段核对登记卷身份和在线状态。区分已证实丢失、换挂载点、断开的盘符/挂载、权限不足以及路径身份漂移。 | 卷暂时离线或身份未知时保留注册。永久丢失须由可靠证据和所有者裁决共同确认，另查未推送 refs、局部对象、reflog 和备份。 |
| `Unavailable`、bare、HEAD/对象异常 | 分开检查仓库类型、管理目录和已授范围内的 refs、对象及双向路径；保留 Git 报告的注解。 | 单个标记不授权执行修复。bare 与主工作树排除在 linked 恢复入口外；缺对象、HEAD 修正另行审定。 |
| `Prepared` 或 `Started`，结果未定 | 回读请求、执行所有者、目标身份、分支/ref、注册和检出足迹。 | `Prepared` 仅代表该阶段的持久记录。发现外部变更或回读不足时保留预约并隔离，禁止按阶段盲重试。 |
| `Pending` 或 `Disabled` 检出 | 核对已验证注册、检出日志、暂存和发布路径身份，区分待检出与写入已尝试。 | 正常 `Pending` 可经独立检出授权接续。已禁用或含残留的请求先走恢复审定，禁止自动重检出或接入。 |

### 恢复操作的预览与写入范围

首次显式请求只生成只读预览。为每次执行另取本机用户二次确认，绑定仓库/卷/目标身份、注册和意图、操作类型、完整影响对象、数据处置和恢复能力、Git 版本、预览摘要及短期有效期。单次确认仅消费一次。修复中包含的解锁、剪除、移除和文件清理分别确认，禁止用会话级允许、前一动作的批准或诊断入口授权写入。

| 操作 | 只读预览与影响证明 | 独立授权后的动作 |
| --- | --- | --- |
| `unlock` | 核对唯一 linked 注册、锁值、任务租约及目录身份，说明失去锁保护后的影响。 | 对该注册执行原生解锁，回读锁与目标。解锁不执行 prune 或移除，重新加锁需要另行操作。 |
| `repair` | 已知移动前后身份，读取 Git 文件、`gitdir` 回指、`commondir`、管理目录归属及关联工作树。根据支持的版本和操作模式证明会触及的全部记录，无法界定多工作树范围时拒绝。 | 只允许已证实的路径映射，逐个复核原生 repair 输出和双向关联，保留证据供后续恢复。禁止任意编辑 Git 元数据或修复对象。 |
| `prune` | 使用固定过期策略下的 `worktree prune --dry-run --verbose` 和前后清单，验证整个仓库的精确候选集合、管理目录身份和丢失裁决。预览须显示可能删除的 index、reflog 等每工作树元数据。 | 原生命令按仓库执行，不支持按单个候选过滤。只允许在全部候选均经批准且能约束竞争写入时执行。执行前重做同参数预览，任何新增或变化使授权失效。禁止把 `--expire=now` 作为默认策略。 |
| 移除注册 | 区分在线的干净 linked 工作树和失联注册。在线检查已跟踪、未跟踪及忽略内容、锁、子模块、分支/绝对 OID 与保留数据方式；检查失败、分支或对象风险不明时拒绝。 | 对在线、已证实干净且无保留项的工作树，只考虑普通 `worktree remove`。预览须包含工作目录与管理数据的删除及验证过的恢复来源。失联注册走受控 prune，禁止手工删除管理目录、强制移除或顺带删分支。 |
| 清理部分落盘 | 从原请求对照初始状态、属主、全部待处理路径的身份与相对边界。说明是否涉及已存在目录、他人文件、注册、分支或无法复原的内容。 | 仅限可证明由该请求创建且无后续写入的宿主资产，按批准的精确对象处理。优先保留或经同卷验证后移入宿主管理隔离区，单独批准后方可删除。任何身份漂移、数据归属不确定或范围无法证明均保留并报告。 |

执行前在同一协调域持有仓库身份和目标预约，核对运行时是否仍能排除外部并发影响。重算证据并与预览逐项比较，漂移则作废并重新请求批准。执行后回读精确受影响项和同仓余项。部分结果、状态漂移或未知进程结局保留证据并保持接入禁用。刷新清单、任务回收、打开项目及后台维护均不得隐式自愈。原生 Git 手册记录了命令的适用范围。 [git-init](https://git-scm.com/docs/git-init) · [git-clone](https://git-scm.com/docs/git-clone) · [git-worktree](https://git-scm.com/docs/git-worktree) · [git-config](https://git-scm.com/docs/git-config)

## 6. 本机 Git 实测证据

使用 Git for Windows `2.56.0.windows.4`、新建本机临时根和独立配置，源、目标、模板及工作树均为夹具，未连接网络或修改真实项目配置。未运行实际 prune 或删除工作树目录。工作树路径缺失通过在夹具内改名模拟，目录内容仍保留。

| 夹具与命令 | 实际观察 |
| --- | --- |
| 配置外部 `init.templateDir`，执行 `init --template= --initial-branch=main` | 新仓库分支名是 `main`，模板中的 `post-checkout` 没有复制到新仓库。 |
| 本地 `clone --no-checkout --no-recurse-submodules`，随后手动检出 | Clone 成功后跟踪文件缺失，手动检出成功。Git 也接受了另一个已存在的空目标，Soxu 的首版缺失目标规则更严格。 |
| 仅允许 `file`，向 Clone 传入 `ext::echo` | Git 返回 128 和 `transport 'ext' not allowed`。 |
| 对 linked Worktree 执行 `lock --reason`、`list --porcelain`、`unlock` | 清单先显示锁及理由，随后锁标记消失。 |
| 在同卷移动 linked Worktree，执行 `worktree repair <新路径>` | Git 成功，清单注册路径更新为新路径。 |
| 在同卷移动另一 linked Worktree，执行 `prune --dry-run --verbose --expire=now` | 原位置显示 `prunable`。预览列出对应管理目录，复查仍存在该注册。此夹具未验证真实卷离线、数据无损或实际 prune。 |

### 待验证的平台与版本差异

- Windows 上验证 reparse/junction、卷 GUID 与盘符变更、路径别名/大小写、句柄保留、共享权限、原子发布及进程树收敛。Unix 上验证 inode/设备号、符号链接、挂载替换、权限变化及非 UTF-8 路径。各平台分别验证大小写和 Unicode 归一化对目标独占、Git 树路径验收及授权摘要的影响。
- 跨版本验证 `--no-local` 的本地对象隔离和 `--` 参数边界，HTTP TLS/重定向、helper 环境与真实配额控制、取消后进程树以及 Git 自身清理差异。验证禁用系统/全局配置和外部模板、过滤器、凭据、子模块及按需 fetch 的有效性。
- 验证 repair 在主工作树移动、多 linked 记录、相对路径或不同 Git 版本下的触及范围。验证真实卷离线与永久丢失、被锁定或冲突的 prune 候选，以及外部 Git 在预览至执行间发生变更的拒绝路径。平台证据缺失时保持相应写入口关闭。

| 恢复执行及重启复核 | `crates/soxu-git/src/worktree_recovery/execute.rs`、`crates/soxu-git/src/worktree_recovery/journal.rs`、`crates/soxu-git/tests/worktree_recovery_execute.rs` | 在预览契约合入后实施，复用同一协调域。若需调整共享注册、检出模块或持久格式，先单独声明并串行合入。 |
| Git 模块导出及本地宿主接入 | Git 的共享 `crates/soxu-git/src/lib.rs` 单流负责导出。宿主 Issue 另列明确文件。 | 底层只读预览和本机写入契约稳定后，宿主才接续授权、界面及 Agent 接入。 |

以上为后续路径建议，需按实施 Issue 声明写入范围。当前文档及首批宿主本地能力不需要更改 `soxu-protocol`、根 `Cargo.toml` 或 `Cargo.lock`。若后续跨进程/跨端发布新增请求、事件或批准契约，由独立协议 PR 先行。若平台身份检查或原生进程控制确需新依赖，则单独评估并协调清单改动。

| 类别 | 必测场景与预期 |
| --- | --- |
| Init 路径与布局 | 新目标、显式授权纯空目录、空目录并发插入，非空/隐藏文件、目录内外现有仓库、bare、损坏 gitfile、父级仓库、链接和 reparse。只接受获准且复核通过的布局；在模板/钩子夹具中验证外部动作未触发，明确 unborn 分支名。 |
| Clone 源与目标 | 缺失或空目标、重叠路径、local `--no-local`、外部对象、白名单/非法协议、URL 变形、代理、重定向、进程提示和凭据注入。仅允许精确源和目标，检查 Git 退出后是否留下足迹。使用本地回环夹具验证 HTTP 策略，避免访问外网。 |
| Clone 对象与检出 | 空远端、无效 HEAD、非零完整 OID、gap/缺对象、partial/shallow、gitlinks、符号链接、外部过滤器和平台路径碰撞。对异常禁用发布，验证未触发隐式 fetch、子模块或自动接入。 |
| 执行与重启 | 目标并发预约、重复 ID、同一路径身份替换、`Prepared`/`Started` 崩溃、超时/取消、进程树未收敛、命令成功但复核失败。核对留痕，禁止重放、清理或接入。 |
| 诊断状态 | 有效锁、疑似孤立锁、未知所有者、临时离线/换盘、确认丢失、`Unavailable`、`Pending`、`Disabled`、未完成注册与检出混合。结果明确证据缺口，诊断前后快照一致。 |
| 恢复授权与范围 | 单次确认、过期/重放、漂移、不同注册或动作复用授权、repair 涉及多记录、prune 候选扩张、在线移除含忽略文件、残留混入用户文件。授权与范围不符时零写入，部分失败可诊断且不会自动重试。 |
