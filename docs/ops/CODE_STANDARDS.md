# Soxu 工程编码、测试、审查与发版标准 (CODE STANDARDS)

> 融合高并发多 Agent 实战经验（借鉴 `yetone/magpie` 与本仓实战），作为 `AGENTS.md` 与 `docs/ops/LESSONS.md` 晋升条款的执行准则。所有实现、测试、PR 审查与合入必须逐条对照核验。

---

## 一、变更范围与工程质量（What a Change Contains）

1. **单目标变更边界**：一个提交/PR 只解决一个 Issue 目标，禁止在功能修复中夹带无关重构或阈值放宽。
2. **治一类病，不止改一个样本**：发现模式性 bug 时，顺藤摸瓜搜索全部兄弟平台分支（Windows/Linux）、同类驱动和调用方，在同一次修复中一并覆盖。
3. **修改基准必重算下游不变量**：一旦修改公式、状态机流转、路径解析或分支命名约定，必须顺着调用链核验所有上下游测试与状态守卫。
4. **失败一律闭合（Fail Closed）**：文件读取、解析、哈希或目录句柄校验失败表示「未知」，绝不降级为空列表、默认放行或跳过授权。
5. **不覆写用户显式配置**：读取本机工具/Magpie/宿主配置时，凡用户显式设置的值一律优先保留，严禁擅自覆盖全局配置。
6. **守住预算与隔离边界**：严守 `Cargo.toml`（禁 `unsafe`、禁盲目加依赖）、AOCI Cognition Budget 与目录大小边界，不得为图省事放宽门禁或添加 `#[allow(...)]` 掩盖静态检查告警。

---

## 二、测试与双平台验证纪律（Tests & Verification）

1. **修复必带「回退即 FAIL」回归测试**：新修复在还原旧代码后必须能稳定复现失败 `FAIL`（不能靠跳过或仅编译测试充数）。
2. **测试零外网、零宿主污染**：单元与集成测试一律使用临时目录（`tempfile`）或本地夹具，严禁访问真实外网或读写真实用户主配置（如 `~/.config/magpie`、`~/.codex`、`~/.claude`）。
3. **测试启动的资源结束必回收**：测试内派生的子进程、守护线程或监听句柄必须在返回前等待退出并释放文件锁，防止污染下个用例或触发 Windows 文件占用锁。
4. **拒绝脆弱墙钟等待**：并发或超时验证应通过明确状态信号、同步屏障或显式条件轮询实现，留足高负载 Runner 的时间余量。
5. **主线红灯即当前 P0 缺陷**：严禁以「`main` 上原本就这样」或「只在全量运行才失败」为由绕过红灯继续合入；遇到冻结模块历史缺陷立即走 `[BLOCKED / NEED-DECISION]` 并拆独立热修复 PR 先行治本。
6. **多路并行构建错峰隔离**：每个并行 Worktree 必须使用独立 `CARGO_TARGET_DIR`（Windows 禁用 `mise run`，WSL 前置真实工具链目录绕开 `mise` shims），避免多路抢锁或污染共享缓存。

## 三、审查、合入与联动发版铁律（Review, Merge & Release）

1. **合并最新 `main` 实测后再审查收口**：主控或下游 PR 审查不能只看静态 Diff，必须基于最新 `main` 合并结果在目标平台独立复跑门禁。
2. **合入强制锁定已审 SHA**：主控合并 PR 必须使用 `gh pr merge <pr> --squash --delete-branch --match-head-commit <reviewed_sha>`，防止审查后突发新提交混入主线；且 PR 正文中 `Closes #<issue>` 必须裸写（不得套反引号）。
3. **如实记录精确验证事实**：PR 说明与收口报告必须写明已跑命令、通过计数及尚未验证的平台/入口，严禁把单一平台通过或 `cargo test --no-run` 包装成全平台真机验收。
4. **Worktree 单一归属**：严禁跨分支交叉操作或提前回收仍在运行的 Worktree，提交后必核 `git status -sb` 与 `git show --stat HEAD`。
5. **Tag 不等于发版完成**：主仓仅在 `main` CI 绿灯提交上打 `v*` tag；仅当公开联动发版仓 `TanCan1998/soxu-releases` 完成全平台实机冒烟校验、`SHA256SUMS` + SLSA 构建溯源、全部预期资产发布且语义最高版本成功标注 `Latest` 并镜像回本仓后，才视为一次正式发版完成。
